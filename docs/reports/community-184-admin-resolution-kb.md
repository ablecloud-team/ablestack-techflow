# Community #184 관리자 해결 선택과 KB 마무리

## 확인 결과

- 토론은 SCVM 3대가 GRUB 단계에서 종료되는 현상이었다. 질문자는 Post #481에서 각 SCVM의 디스크 표시를 `device='lun'`에서 `device='disk'`로 변경한 뒤 정상 부팅됐다고 확인했다.
- 선택된 지원 답변 Post #478은 수집 이후 편집되어 로그 경로와 디스크 표시 방식 우회 조치가 추가됐으나 저장된 Turn에는 편집 전 자료 요청만 남아 있었다.
- 해결 선택자 User #12는 실제 Flarum 관리자 그룹 #1 소속이다. 엔진의 정적 운영자 ID 목록에는 선택 전용 계정 #1만 있어 `WAITING_RESOLUTION`을 반환했다. Poller는 KB 게시·최종 선택을 완료 조건으로 삼아 해결 대기를 계속 유지했다.
- 같은 해결 이벤트의 과거 `RESOLUTION_REVIEW_REQUIRED` 멱등 결과가 있어 관리자 확인만 추가해도 기존 이벤트 결과가 재사용된다.
- 기존 AI 후속 답변 Post #487에는 공개 경로 마스킹으로 실행 불가능해진 명령이 포함됐다. 정상 부팅 확인과 일반 표준 적용 여부는 구분해야 한다.

## 보완 범위

- 운영자가 지정한 기존 ID 정책은 유지한다. 목록 밖 선택자는 인증된 Flarum API에서 현재 선택된 토론·답변·선택자 일치와 실제 기본 관리자 그룹 소속을 검증한다. 이벤트가 주장하는 관리자 역할은 신뢰하지 않는다.
- 권한 조회 실패는 503으로 재시도하며 일반 멤버·다른 답변·다른 선택자에 대한 이벤트는 관리자 해결로 인정하지 않는다. 권한 변경이나 사용자 그룹 추가는 하지 않는다.
- 검증된 관리자 재평가는 해시 기반 별도 멱등 키를 사용해 기존 보류 감사 기록을 지우지 않고 전환하며, 반복 호출로 전환 이벤트를 중복 생성하지 않는다.
- KB 작성 전 선택된 답변의 현재 공개 Markdown을 읽어 편집 후의 해결 내용을 사용한다. 숨김·비공개·다른 토론·빈 본문은 게시하지 않고 재시도한다.
- 운영에 필요한 고정 SCVM 로그 경로는 공개 답변에서도 보존한다. KB의 선택 주체를 질문자라고 잘못 단정하지 않고 포럼에서 선택된 해결 답변으로 표현한다.
- 기존 AI 답변 #487은 같은 위치에서 실제 실행 가능한 읽기 점검과 환경별 해결 결과로 보완한다. 새로운 원인이나 지원 범위를 단정하지 않고 기존 지원 답변 #478과 질문자의 결과 #481을 KB에 반영한다.

## 검증 및 운영 절차

관리자·위조·권한 오류·기존 멱등 보류 재평가·편집된 해결 답변·KB 게시 및 최종 선택을 포함한 Community·Poller·Store·Chat·운영 알림 회귀시험 259건이 격리 컨테이너에서 통과했다. Gateway와 Community Poller만 제한 배포하고 원본 해결 답변은 보존한다. 게시된 KB와 최종 선택을 Flarum·저장 계층·운영 브라우저에서 확인한 후 Poller의 해결 대기가 0건이 되는지 검증한다. 최종 커밋·KB Post ID·서비스 상태는 Issue #141과 연결 PR에 기록한다.
