# Community #209 CCVM 배포 단계·SSH 근거 점검

관련 Issue: #156 · [최신 공개 답변](https://community.ablecloud.io/d/209/8)

## 실제 확인과 원인 범위

- 최초 공개 입력은 원글585의 디렉터리 생성 실패 이미지, 댓글587의 SSH 로그, 댓글589의 `Command execution test failed` 재질문입니다. 원본 이미지를 직접 확인하고 등록된9,124바이트·445×161 Artifact 메타데이터와 대조했습니다.
- 사람의 별도 기술지원 답변이나 해결 선택은 없습니다. 등록된 이미지는 보관 기간 내이며, 붙여 넣은 로그는 별도 첨부파일로 가장하지 않습니다. 고객 주소·호스트명·지문·로그 원문은 이 보고서에 복제하지 않습니다.
- 기존 AI는 성공한 `Accepted publickey`에 집중하고 일부 `no matching host key type` 행을 누락했습니다. 운영의 실제 저장 댓글587은4,000자이고 협상 실패가 있지만, 생성된3,317자 프롬프트에는 그 실패가 없고 인증 성공 행만 남는 현상을 읽기 전용으로 재현했습니다.
- 이미지의 주소 일부를 오류 코드로 해석하고 폴더 생성 오류를 다른 배포 분기의 단계로 설명한 부분도 확인했습니다. root 관리 키의 제품 내부 적용 범위를 업무 VM 전체로 확대하면 안 됩니다.

## 정확한 제품·공식 소스

검토 기준은 운영 검색 근거에 포함된 공개 커밋 `c8b37dd6a4c35a8ba18169189a553595b24e54ab`입니다. 고객의 실제 설치 커밋과 동일하다고 주장하지 않습니다. 현재 공개 Diplo ref `d0e122f01bbf3710cb926f03e0d1164d6493b4aa`에서도 아래 사전 검사 구현이 유지되는 것을 확인했습니다.

- [cluster_config.py 251~303](https://github.com/ablecloud-team/ablestack-cockpit-plugin/blob/c8b37dd6a4c35a8ba18169189a553595b24e54ab/python/cluster/cluster_config.py#L251): `insertScvmHost`는 화면 JSON의 `ablecube`·`scvmMngt`를 ping 검사한 뒤 같은 실행 계정·설정으로 SSH `echo ok`를 순서대로 수행합니다. 종료 성공과 `.strip()` 후 정확한 `ok`를 요구하며 예외는 일반 오류로 축약할 수 있습니다. 이후 원격 설정 쓰기가 있어 함수 전체를 읽기 전용 검사로 호출하면 안 됩니다.
- [create_ccvm_cloudinit.py 137~159](https://github.com/ablecloud-team/ablestack-cockpit-plugin/blob/c8b37dd6a4c35a8ba18169189a553595b24e54ab/python/vm/create_ccvm_cloudinit.py#L137): ISO 생성 성공 후 PCS 대상에 명시적 `root@대상` SSH로 `<pluginpath>/tools/vmconfig/ccvm`를 준비하며 최대3회 후에도 실패하면 해당 문구를 반환합니다. 사전 검사와 계정·대상·호스트 키 옵션이 다를 수 있습니다.
- [ssh-scan.sh](https://github.com/ablecloud-team/ablestack-cockpit-plugin/blob/c8b37dd6a4c35a8ba18169189a553595b24e54ab/shell/host/ssh-scan.sh#L10)와 [공식 ssh-keyscan](https://man.openbsd.org/ssh-keyscan): 제품의 호스트 키 수집 경로 및 여러 키 유형 조회를 확인했습니다. 특정 `[preauth]` 오류가 스캔에서 발생했다고 단정하지는 않습니다. 로그인 사용자 키 인증과 서버 호스트 키 협상, 각 연결의 출발지·대상·계정·시각을 구분합니다.
- [공식 ssh 설정](https://man.openbsd.org/ssh_config)과 [ssh -G](https://man.openbsd.org/ssh.1#G): 비대화형 검사와 현재 설정 조회를 대조했습니다. 고객 안내는 호스트 신원 검증을 유지하며 검증 해제·전역 알고리즘 완화·키 일괄 삭제를 제시하지 않습니다.

## 검사 중 추가된 댓글과 안전한 처리

게시 직전 댓글591이 추가돼 이전 입력용 수정은 중단했습니다. 질문자는 사전 검사가 해결된 뒤 폴더 오류가 다시 났다고 보고했습니다. 이를 전체 배포 해결로 처리하지 않고 최신 실패의 명시적 root·PCS 대상·파일시스템 확인으로 초점을 바꿨습니다.

정상 자동 처리와 경쟁하지 않도록 상태를 확인한 결과, 해당 입력의 자동 실행3건이 실행 위치·권한·로그 범위 등 품질 검사 누락으로503 `COMMUNITY_RESPONSE_NOT_ACTIONABLE`을 반환해 실패했고 실행 중인 작업은 없었습니다. 운영 품질 검사 두 가지를 통과한 검토 답변을 정상 Case 생성·발행 메서드와 원문/소유권/공개 상태/멱등 경계로 처리했습니다. 검사 기준을 낮추거나 Flow·서비스 설정을 변경하지 않았습니다.

- 댓글591에 답변592(공개 순서8)를 한 건 게시했습니다. 중간에 발행은 성공했으나 처리 기록 확인을 재시도해야 했으며, 기존 발행 마커와 검토 해시를 이용해 **같은592를 재사용**했습니다. 새 답변을 중복 생성하지 않았습니다.
- 기존 AI586·588·590은 같은 게시물에서 단계·주소·SSH 근거 해석을 정정하고 최신 안내로 연결했습니다. 사람의 글은 수정하지 않았습니다.
- 공개 본문, 기존/신규 대화 Turn, 응답·감사 기록, Case 버전4와 `PUBLISHED / WAITING_RESOLUTION`을 확인했습니다. 해결 선택과 KB 생성은 하지 않았습니다.
- Poller는 pending0/failed0으로 정리됐습니다. 현재 게이트웨이는0.16.31이며 이번 코드 후보를 운영에 배포하거나 자동 병합하지 않았습니다.

## 엔진 후보 변경

- 사람 댓글의 제한된 중간 SSH 실패 행을 로그 자료로 보존합니다. 원문 앞·뒤를 유지하면서 발췌는 최대2개, 행당140자, 주어진 예산의1/3 이내로 제한합니다. 전체 프롬프트·UTF-8 검색 경계는 유지합니다.
- 코드 서식의 `ssh` 식별자와 실제 신규 SSH 진단 명령, 이미 안내한 동일 명령을 구분하는 진행성 시험을 추가했습니다. 이는 실행 권한 부여나 완전한 셸 안전성 판정기가 아닙니다.
- 최신 사람 질문의 실패 단계를 기준으로 폴더 오류에서는 실제 cloud-init helper를, 사전 오류에서는 `insertScvmHost`를 우선 검색합니다. 무관한 SSH·CCVM 보안 질문을 이 경로로 강제하지 않습니다.
- 현재 제품 근거와 공식 호스트 키 스캔 근거, 양 단계의 계정·대상 차이를 참고 자료와 지침에 추가했습니다. IP 일부의 오류 코드 오인 및 관리 키의 업무 VM 확대를 방지합니다.
- 제안 버전0.16.32, OpenAPI39 operations. DB migration·권한·서비스 변경은 없습니다.

## 시험

- 수정 전 중간 협상 오류 누락과 구체 helper 검색어 부재의2개 재현시험 실패를 확인했습니다.
- 압축/재작성의 양쪽 로그 근거 보존, 짧은 입력 불변·길이 예산, SSH 명령 진행성, 최신 단계 우선, 무관한 문맥 회귀, IP/키 범위 지침, 부분 해결 후 새 실패의 미해결 처리 등을 검증했습니다.
- WSL ext4의 격리 Git 스냅샷과 Python3.12에서 **전체502개 시험 통과**. OpenAPI export39 operations와 `git diff --check`를 확인했습니다.
- 새 코드로 운영 모델 생성을 다시 실행하거나 고객 시스템에서 SSH·디렉터리 명령을 수행한 것이 아닙니다. 공개 안내는 제품 소스 검토와 운영 중인 기존 품질 검사에 기반한 검토 답변입니다.
