# Issue #73 Community 인터페이스 현대화 완료 보고서

## 결론

ABLESTACK 브랜드 기반 Flarum 전용 테마 확장을 구현하고 WSL Ubuntu 24.04의 Flarum 1.8.18 복제 환경에서 활성화, 기능 검증, 비활성화 롤백, 재활성화를 완료했다. 데스크톱 1440x900과 모바일 390x844에서 홈·목록·태그·검색·로그인·작성·프로필·설정·보안·해결 답변·게시물 작업 버튼을 실제 렌더링했으며 한글 원문 번역 키와 태그·프로필·설정·보안 직접 노출 영문은 모두 0건이었다.

Flarum Core, Vendor 원본, DB Schema와 Community 콘텐츠는 수정하지 않았다. 사용자 39명, 토의 117건, 게시물 305건, 콘텐츠와 첨부 해시는 전체 주기 전후 동일했다. 이후 승인된 후속 개선을 WSL과 운영 Community에 같은 독립 테마 확장으로 적용했으며 최종 판정은 **PASS**다.

## 기준선 분석

운영 Community는 제품 기능은 정상이나 화면 계층이 약하고 목록 행 간격이 좁았다. 모바일에서는 뷰포트 전환 시 탐색 메뉴가 콘텐츠를 덮는 모습과 긴 한글 제목의 가독성 저하를 확인했다. 상세 화면에서는 TechFlow-Assistant 진행 답변과 질문자가 선택한 최종 Knowledge Base가 같은 구조로 보였고 `Answered`, `Best Answer`, `Select Best Answer`가 영문으로 남았다.

운영 기준선은 읽기 전용으로만 수집했다. 질문, 답변, 설정과 서비스는 변경하지 않았다.

## 구현 내용

### 독립 테마 확장

- Package: `ablecloud/community-theme`
- 대상: Flarum Core `^1.8`
- 구현: LESS, Composer Extension, 한글 Locale warm-up
- 미포함: Core Patch, Vendor 원본 수정, DB Migration, 별도 프런트엔드 Framework

ABLESTACK Primary `#155EEF`, Ink `#15253E`, Canvas `#F3F7FC`를 기준으로 헤더, Hero, 탐색, 토의 카드, 게시물, 검색, 로그인, 작성기와 첨부 버튼을 블루 계열로 통일했다. 배경에는 옅은 블루 Gradient를 사용하고 카드에는 14~16px Radius, 블루 계열 경계와 낮은 그림자를 적용했다.

브라우저 계산값으로 상세 게시물 카드는 데스크톱 `21px 25px 23px`, 모바일 `18px 16px 20px`의 내부 여백을 확보했다. 최종 토론 목록은 Reddit New의 게시물 한 건 구조를 참고해 작성자·분류·작성 시각, 제목, 첫 글 요약, 태그, 댓글 수를 위에서 아래로 읽도록 재구성했다. 제목과 요약은 각각 최대 두 줄이며 행 높이는 콘텐츠와 해결 상태에 따라 `137~187px`로 달라진다.

첫 글 요약은 Flarum 목록 응답에 이미 포함된 `firstPost.contentPlain()`을 사용하므로 토론마다 별도 API 요청을 만들지 않는다. 해결 배지와 작성 정보는 같은 헤더 Grid의 독립 열에 배치하고 8px 간격을 보장한다. 사용자 아바타는 행 좌측 상단에 고정하며 해결 여부와 무관하게 본문 안에 완전히 표시된다. 운영 토론 #173에서 배지-작성 정보 겹침 `false`, 일반 토론 #144와 해결 토론 #173 모두 아바타가 본문 경계 안에 있음을 브라우저 계산값으로 확인했다.

기존 목록 링크는 `/d/{slug}/4`처럼 마지막 게시물 번호를 포함해 토론을 열자마자 마지막 응답으로 이동했다. 목록의 `.DiscussionListItem-main` 링크에 한해서 게시물 번호를 제거한 토론 기본 주소로 정규화하고, 클릭 시 해당 주소를 새 문서로 열도록 했다. 브라우저 검증에서 경로는 `/d/144-gasangmeosin-webkonsol-yeongyeol-oryu`, `scrollY=0`, 첫 게시물은 화면 안에 표시됐다. 알림이나 상세 내부의 특정 답변 링크는 변경하지 않는다.

토론 행 오른쪽의 더보기 버튼은 Hover 여부와 관계없이 항상 표시하고 행의 세로 중앙에 배치했다. 기본 상태의 테두리·배경·그림자를 모두 제거해 세로 이클립스 아이콘만 남겼고, hover·focus·열림 상태에서만 옅은 원형 배경이 보인다. 브라우저 실측 중심 오차는 `0px`다. 열린 행·버튼·메뉴의 계층은 각각 `1050`·`1070`·`1080`으로 분리해 메뉴가 뒤쪽 토론 카드에 가려지지 않게 했다. 실제 열린 메뉴 좌표에서 최상위 요소가 메뉴 내부 요소임을 확인했다.

상세 화면 상단에서 여는 토론 목록 패널은 기존 `y=52px`에서 시작해 높이 68px인 Header와 15px 겹쳤다. 패널 시작점을 `y=68px`, 높이를 `calc(100vh - 68px)`로 조정해 Header 겹침을 `0px`로 만들었다. 400px 패널 안의 토론은 8px 간격 카드로 정리하고 현재 토론은 Primary 왼쪽 선과 옅은 블루 배경으로 표시했다. 스크롤바는 `thin`과 WebKit `6px`을 함께 지정했다.

환영 Hero는 데스크톱 기준 `361px`에서 `127.89px`로 줄였다. 상단 로고 높이는 `34px`, 타이틀 글자는 `28px`로 맞춰 타이틀이 로고보다 작고 다른 본문 글자와도 지나치게 차이 나지 않게 했다. 왼쪽 카테고리 메뉴는 `190px`에서 `280px`로 넓혔고, 태그 페이지의 `토의 시작` 버튼은 도구 모음 내부 오른쪽 넘침 `0px`로 확인했다. 태그 도구 모음은 아이콘·글자를 10px 간격으로 세로 중앙 정렬하고 선택 강조선을 버튼 하단으로 옮겨 콘텐츠와의 겹침을 제거했다.

태그 페이지는 서로 붙어 있던 원색 블록을 데스크톱 3열·18px 간격의 독립 카드 Grid로 바꿨다. 카드 본문은 흰색, 제목은 Ink, 설명은 Muted 색상으로 통일하고 태그 고유 색상은 4px 상단 강조선으로만 유지했다. 최근 토론은 옅은 블루 배경·경계·`최근 토론` 레이블을 갖는 76px 독립 패널로 분리했다. 보조 태그 7건은 주요 태그 아래의 별도 구역에 실제 설명과 함께 데스크톱 4열·12px, 모바일 1열·10px로 배치했다. 모바일 주요 태그는 폭 336px의 한 열 카드와 14px 간격으로 전환하며 가로 넘침은 `0px`다.

최근 토론 날짜 중 절대 날짜는 `26년 6월 12일`, `26년 7월 7일`처럼 `00년 0월 0일` 형식으로 통일했다. `7일 전`, `9일 전`과 같은 상대 날짜는 의미를 유지했다. 검증 중 Flarum의 Font Awesome 웹폰트가 Cache 재생성 뒤 요청되지 않아 아이콘이 점·더하기·사각형 또는 운영체제 기호로 다르게 보이는 결함도 확인했다. 의미 Class는 유지하고 검색·내비게이션·태그·프로필·설정·보안·게시물 작업·Footer의 45개 이상 아이콘을 CSS 내장 SVG Mask로 통일해 잘못된 대체 아이콘을 `0건`으로 줄였다. 토론 정렬 메뉴는 선택 항목의 SVG 체크만 표시하고, 비선택 항목의 정렬용 빈 아이콘 자리는 숨겨 검은 사각형 3건도 제거했다.

게시물 작성자 아바타 옆 관리자·기술지원·연구소 배지는 각각 렌치·번개·책 SVG Mask로 표시한다. 추가 화면 순회에서 토론 타임라인의 처음·끝 이동, 댓글 수의 Core 가상 요소, 설정의 이메일·알림 시계, 작성기의 전송·이미지·이모지 아이콘도 같은 체계에 포함했다. 브라우저 기본 검색 초기화 글리프는 전용 닫기 SVG로 대체해 검색어 입력 뒤에도 사각형이 나타나지 않는다. 검색 입력은 공통 3px 외곽선과 전용 링이 겹치던 구조에서 검색 전용 외곽선을 `none`으로 바꾸고 `2px` 브랜드 링만 유지해 모서리의 파란 꼭지점 현상을 제거했다.

로그인 헤더에서 신고·알림뿐 아니라 사용자 메뉴의 프로필·설정·관리·로그아웃 아이콘도 점으로 표시되고 있었다. 공통 SVG Mask 체계에 모두 포함해 별도 폰트 요청 없이 항상 보이게 했다. 검색·언어·신고·알림·프로필은 모두 `44px` 높이와 브라우저 실측 `y=16px`에 배치되어 세로 위치·높이 편차가 `0px`다. 언어 메뉴의 화살표, 토론 정렬, 새로고침과 더보기 아이콘도 같은 선형 체계로 표시한다.

언어 드롭다운의 비선택 `English` 항목은 아이콘 의미 Class가 없는 빈 정렬 자리였지만 공통 마스크 배경 때문에 검은 사각형으로 보였다. 빈 아이콘만 `visibility: hidden`으로 처리해 정렬 폭은 유지하고 사각형은 제거했다. 추가 전 화면 검사에서는 실제 SVG가 있어도 Flarum 기본 `margin-left: -25px` 때문에 언어·사용자 메뉴 아이콘이 카드 왼쪽 바깥으로 밀려나는 원인을 확인했다. 아이콘을 `position: static`, `margin: 0`, `flex: 0 0 19px`로 고정하고 메뉴 폭을 `180px`로 넓혀 프로필·설정·관리·로그아웃과 언어 선택을 같은 아이콘·글자 열에 맞췄다. 항목 Hover 패딩도 기본과 같은 좌우 `12px`로 고정했다. 브라우저 계산값에서 두 메뉴의 아이콘은 모두 행 경계 안에 있고 아이콘-글자 세로 중심 편차는 `0.008px`, 같은 메뉴의 글자 시작선 편차는 `0px`, 좌우 넘침은 `0px`다.

좌측 카테고리와 프로필·설정·보안 메뉴에는 행 전체 hover·키보드 focus·active 상태를 추가했다. 태그 고유 색상이 메뉴 아이콘에 섞이지 않도록 기본 글자는 네이비, 아이콘은 블루 그레이로 통일하고 각각 16px·18px로 키워 46px 행의 중앙에 맞췄다. 선택 표시를 둥근 `inset` 선에서 독립된 3px 직선과 Primary 테두리로 바꿔 `ㄷ`자처럼 보이던 결함을 제거했다. hover와 focus는 옅은 블루 배경, 오른쪽 2px 이동과 아이콘 확대를 사용한다. 프로필 메뉴의 게시물·토의·좋아요·내 미디어·언급·설정·보안 7개 아이콘은 브라우저 계산값에서 모두 유효한 내장 SVG Mask로 확인했다.

Hero의 위·아래 패딩은 데스크톱 `19px`, 모바일 `17px`로 대칭화했다. 데스크톱에서 타이틀 위와 마지막 설명 아래의 실제 여백 차이는 경계선 포함 `1px`다. 목록 작성자 아바타의 기존 13px 상단 여백을 제거해 아바타와 제목의 세로 중심 차이를 `12px`에서 `0px`로 줄였다.

게시물 작업은 답장·좋아요·해결 선택·더 보기를 모두 아이콘과 한글 텍스트 조합으로 표시한다. 기존 `top: calc(100% + 8px)` 방식은 본문이 길어질수록 카드와 버튼 사이가 8px에서 39px·49px·66px로 늘어나는 원인이었다. 이를 카드 하단 기준 고정 앵커로 바꿔 짧은 본문과 긴 본문 모두 설계 간격 8px, 보더를 제외한 브라우저 실측 7px로 통일했으며 게시물별 편차는 0px다. 작업 그룹은 Flex로 배치하고 데스크톱 8px, 모바일 6px 간격을 적용해 버튼 사이 겹침을 0px로 유지한다. 모바일 390px에서도 네 버튼이 한 줄에 유지되며 가로 넘침은 0px이다. 버튼 뒤를 지나던 Flarum 기본 게시물 구분선은 카드 보더와 역할이 중복되어 제거했다.

작성창과 태그 선택창에서 확인한 규칙을 특정 창 전용으로 두지 않고 Flarum의 공통 `Modal` 구성요소에 적용했다. 모든 대화상자는 같은 58px 헤더, 블루 계열 경계, 원형 닫기 버튼, 주요 확인 버튼, 입력 배경과 2px의 부드러운 포커스 링을 사용한다. 브라우저 기본 고대비 이중 외곽선은 제거하되 키보드 포커스 자체는 색과 링으로 계속 구분된다. 태그 선택창의 직접 노출 영문 `Choose`, `OK`, `Bypass tag requirements`는 `주 태그를 선택하세요`, `확인`, `태그 필수 조건 무시`로 변경했다.

홈 좌측 상단의 작동하지 않는 버튼은 Flarum의 모바일 `Navigation-drawer`를 이전 테마 CSS가 데스크톱에 강제로 노출한 것이었다. 클릭하면 `drawerOpen` 상태만 추가되고 데스크톱 서랍은 열리지 않았다. 데스크톱에서는 이 중복 버튼을 `0x0`으로 비노출 처리하고, 모바일에서는 버튼 `40x46px`, 실제 서랍 `270px`가 열리는 기존 동작을 유지했다.

프로필은 공통 배경색만 적용되던 상태에서 전용 레이아웃을 추가했다. 사용자 Hero를 165px 블루 Gradient 영역으로 정리하고 96px 아바타, 이름, 가입·활동 정보를 명확히 구분했다. 데스크톱 메뉴는 `280px`, 콘텐츠는 `780px`로 배치했으며 빈 화면을 독립 카드로 만들었다. 모바일은 프로필 정보를 압축하고 메뉴와 콘텐츠를 한 열로 전환한다. `Likes`, `My media`, `Security`, `best answers`는 `좋아요`, `내 미디어`, `보안`, `해결 답변`으로 번역했으며 Locale warm-up이 네 핵심 키를 실제 값으로 검증하도록 강화했다.

설정과 보안 화면은 프로필 전용 디자인 체계 안으로 통합했다. 계정·알림·개발자 토큰·활성 세션·전역 로그아웃을 16px Radius의 흰색 카드로 묶고, 블루 경계·그림자·버튼 상태를 공통화했다. 알림 표는 옅은 블루 헤더와 88px 웹·이메일 열로 정리했다. 모바일에서는 336px 카드 안에 302px 표를 배치해 페이지 가로 넘침을 `0px`로 유지했다. `New Token`과 Best Answer·Rich Text 확장 알림 문구를 포함한 직접 노출 영문은 0건이다.

고정 Footer의 ABLECLOUD Home, Blog, Online Docs 링크는 데스크톱 38px·모바일 36px 원형 SVG 아이콘으로 바꿨다. 기존 링크 문구는 DOM의 접근 가능한 이름으로 유지하고 콘텐츠 하단에는 Footer보다 큰 64px·58px 여백을 확보했다. 데스크톱에서 Header·본문·Footer는 모두 브라우저 실측 `x=282.5px`, `width=1100px`, 좌우 내부 여백 `15px`로 일치하며 모바일 Footer 링크 그룹은 중앙 정렬된다.

## 2026-08-19 운영 후속 적용

운영 승인 후 사용자 프로필·설정 메뉴 겹침 보완과 첫 화면 Reddit형 평면 피드를
WSL과 운영 Community에 적용했다. 데스크톱 첫 화면은 Welcome Hero, 280px 좌측
메뉴와 Footer를 고정한다. 우측 `.IndexPage-results` 전체가 스크롤되므로 `최신`
선택 콤보가 있는 도구막대와 토론 행이 함께 이동한다. 좌측 메뉴는 높이가 부족할
때 내부 스크롤할 수 있지만 스크롤바는 표시하지 않는다. 우측 스크롤바 역시
숨기되 마우스 휠·트랙패드·키보드 스크롤 동작은 유지한다.

목록 바깥 Container와 개별 행의 Border·Background·Shadow를 모두 제거했다.
Reddit New의 평면 피드처럼 투명한 배경 위에서 1px 구분선만 사용하고,
ABLESTACK의 블루 색상·폰트·태그·댓글 수·더보기 기능은 유지했다.

WSL과 운영 1280x720에서 문서 `scrollY=0`, 좌측 메뉴 Y좌표 `179.890625`를
유지했다. 우측 영역 `scrollTop`은 `0→360`, 도구막대 Y좌표는
`209.890625→-150.109375`로 함께 이동했으며 `.DiscussionList`의 `scrollTop`은
`0`을 유지했다. 좌측 메뉴는 `0→260`으로 내부 스크롤됐지만 스크롤바 계산값은
`none`이었다. 행 높이는 `58px`, 외부 HTTPS는 `200`, Nginx·PHP-FPM·MariaDB는
모두 `active`다. 운영 적용 전 백업은
`/var/backups/techflow-flarum/theme-reddit-flat-feed-hidden-scroll-20260819T115539Z`에
보존했다.
SCP 임시 경로가 0700인 경우에도 배포 스크립트가 Extension 경로를
Composer와 PHP-FPM이 읽을 수 있는 권한으로 정규화하는 것을 운영 재적용
`RESULT=PASS`로 확인했다. 상세 증적은
`docs/evidence/issue-73/community-index-fixed-feed-validation.json`에 기록했다.

### Reddit형 게시물 한 건 구조 최종 적용

평면 피드의 색상·폰트·1px 구분선은 유지하면서 각 토론 한 건의 내부 구조만
Reddit New에 맞춰 재구성했다. 사용자 아바타 다음에 해결 상태, 대표 카테고리,
작성자와 작성 시각을 한 행으로 표시하고, 제목·첫 게시물 요약·전체 태그·댓글 수를
차례로 배치한다. 요약은 이미 내려온 Flarum Store 데이터만 사용하며 항목별 추가
네트워크 요청은 없다.

초기 운영 확인에서 해결 배지 폭과 기존 배지 Container 폭이 달라 작성 정보를

### 좁은 토론 목록 재배열과 작성기 아이콘 복구

상세 화면 왼쪽에 마우스를 가져갔을 때 표시되는 토론 목록의 400px 폭은 유지했다.
기존에는 데스크톱 목록의 가로 Flex 규칙이 좁은 목록에도 상속되어 제목, 요약과
썸네일이 한 행에서 서로 폭을 빼앗고, 오른쪽 여백도 104px이어서 제목이 몇 글자만
보였다.

좁은 목록만 별도 Grid로 분리해 다음 순서로 재배열했다.

1. 왼쪽에는 작성자 아바타를 고정한다.
2. 첫 행에는 카테고리·작성자·날짜를 표시한다.
3. 제목은 독립 행에서 최대 두 줄을 사용한다.
4. 요약은 제목 아래 독립 행에서 최대 두 줄을 사용한다.
5. 이미지가 있으면 72×54px 썸네일을 오른쪽 전용 열에 표시한다.
6. 댓글 수는 텍스트와 겹치지 않는 카드 오른쪽 아래에 둔다.

이에 따라 목록 폭은 400px 그대로이고 본문 오른쪽 여백은 104px에서 12px로
줄었다. 제목·요약·썸네일이 하나의 가로 Flex 행을 공유하지 않으므로 긴 한글 제목과

### 토론 목록 레이어 복원과 작성기 충돌 방지

목록에서 상세 화면을 열 때 항상 첫 게시물부터 보이도록 만든 기존 처리가
`window.location.assign()`으로 전체 페이지 이동을 강제하고 있었다. 이 과정에서
Flarum이 메모리에 보관하던 토론 목록 상태가 사라져 화면 왼쪽 가장자리에 마우스를
가져가도 400px 토론 목록 레이어가 만들어지지 않았다.

전체 페이지 이동을 제거하고 Flarum의 SPA 화면 전환을 유지하도록 변경했다. 링크는
첫 게시물 경로로 정규화하되 기본 클릭 동작을 막지 않고, 화면 전환 직후 스크롤만
0으로 맞춘다. 목록에서 상세로 이동한 WSL·운영 브라우저에서 각각 20개 항목의
`DiscussionPage-list`가 다시 생성되고 `scrollY=0`을 확인했다. 상세 화면을 직접
새로고침해도 직전에 표시한 목록 Snapshot으로 레이어를 복원하며 현재 토론 1건을
활성 상태로 표시한다.

작성기 하단은 Flarum의 300px Inline 높이보다 내부 편집기와 Toolbar가 더 길어
게시 버튼이 화면 하단에 걸렸다. 데스크톱 활성 작성기의 최소 높이를 336px로
확보하고 Toolbar를 안쪽으로 배치했다. 편집기 하단 여백도 늘려 마지막 문장이
Toolbar 아래에 가려지지 않도록 했다.

토론 목록 레이어가 열린 상태에서 새 토론이나 답변 작성기를 열면 두 화면이
겹쳤다. 작성기가 `visible`인 동안 목록 레이어만 일시적으로 숨기고, 고정된 Pane이
작성기 폭을 밀지 않도록 Composer Container의 왼쪽 값을 0으로 복원했다. 작성기를
닫으면 목록 레이어와 고정 상태가 다시 표시된다.

### 좌측 목록 메뉴와 토론 작성기 레이어 최종 교정

좁은 400px 토론 목록의 더보기 메뉴가 카드 위로 튀어나온 원인은 데스크톱 목록의
`top: 50%`와 `translateY(-50%)`가 그대로 상속된 것이었다. 좁은 목록에서는 메뉴를
카드 상단 10px, 오른쪽 10px에 별도로 고정하고 버튼 영역을 32×32px로 통일했다.
WSL과 운영 브라우저 모두 카드 실제 경계에서 메뉴 상단까지 11px이며 버튼 전체가
카드 안에 포함되고 Transform은 `none`이다.

토론 생성 작성기에서는 기존 보완 CSS가 하단 도구막대를 20px 위로 이동시켜 본문
편집 영역과 실제로 겹쳤다. 작성기 내부를 세로 Flex 구조로 바꾸고 편집 영역과
도구막대를 각각 독립 행으로 배치했다. 두 영역의 경계 간격은 0px이지만 교차 영역은
없으며, 65.5px 도구막대 전체가 작성기 하단에서 15.5px 안쪽에 남는다. 게시 버튼은
작성기 하단에서 29.5px 떨어져 있다.

작성기와 목록이 겹치던 문제는 두 경로를 함께 차단했다. JavaScript가 새 토론 또는
답변 작성기의 `visible` 상태를 `ablecloud-composer-open` 클래스로 동기화하고 기존
Pane Controller를 즉시 닫는다. 동시에 작성 중인 화면의 토론 행은 Hover 상태여도
Z-index를 0으로 유지해 배경 목록이 작성기 앞으로 올라오지 못한다. 목록을 먼저
고정해 화면에 표시한 뒤 답변 작성기를 연 운영 브라우저 검증에서도 Pane은
`display:none`, 작성기와의 교차는 `false`였다.
