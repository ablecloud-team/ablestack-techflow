# Issue #73 Community 인터페이스 현대화 완료 보고서

## 결론

ABLESTACK 브랜드 기반 Flarum 전용 테마 확장을 구현하고 WSL Ubuntu 24.04의 Flarum 1.8.18 복제 환경에서 활성화, 기능 검증, 비활성화 롤백, 재활성화를 완료했다. 데스크톱 1440x900과 모바일 390x844에서 홈·목록·태그·검색·로그인·작성·프로필·설정·보안·해결 답변·게시물 작업 버튼을 실제 렌더링했으며 한글 원문 번역 키와 태그·프로필·설정·보안 직접 노출 영문은 모두 0건이었다.

Flarum Core, Vendor 원본, DB Schema와 Community 콘텐츠는 수정하지 않았다. 사용자 39명, 토의 117건, 게시물 305건, 콘텐츠와 첨부 해시는 전체 주기 전후 동일했다. 운영 Community에는 적용하지 않았으며 판정은 **운영 적용 전 Conditional GO**다.

## 기준선 분석

운영 Community는 제품 기능은 정상이나 화면 계층이 약하고 목록 행 간격이 좁았다. 모바일에서는 뷰포트 전환 시 탐색 메뉴가 콘텐츠를 덮는 모습과 긴 한글 제목의 가독성 저하를 확인했다. 상세 화면에서는 TechFlow-Assistant 진행 답변과 질문자가 선택한 최종 Knowledge Base가 같은 구조로 보였고 `Answered`, `Best Answer`, `Select Best Answer`가 영문으로 남았다.

운영 기준선은 읽기 전용으로만 수집했다. 질문, 답변, 설정과 서비스는 변경하지 않았다.

## 구현 내용

### 독립 테마 확장

- Package: `ablecloud/community-theme`
- 대상: Flarum Core `^1.8`
- 구현: LESS, Composer Extension, 한글 Locale warm-up
- 미포함: Core Patch, Vendor 원본 수정, DB Migration, 별도 프런트엔드 Framework

ABLESTACK Primary `#155EEF`, Ink `#15253E`, Canvas `#F3F7FC`를 기준으로 헤더, Hero, 탐색, 토의 카드, 게시물, 검색, 로그인, 작성기와 첨부 버튼을 블루 계열로 통일했다. 배경에는 옅은 블루 Gradient를 사용하고 카드에는 14~16px Radius, 블루 계열 경계와 낮은 그림자를 적용했다.

브라우저 계산값으로 상세 게시물 카드는 데스크톱 `21px 25px 23px`, 모바일 `18px 16px 20px`의 내부 여백을 확보했다. 데스크톱 토론 목록은 제목·카테고리 태그·댓글 수를 같은 줄에 배치하고 카드 높이를 약 110px에서 `62px`로 줄였다. 모바일은 제목 2줄과 마지막 응답 정보를 유지한다.

토론 행 오른쪽의 더보기 버튼은 Hover 여부와 관계없이 항상 표시하고 행의 세로 중앙에 배치했다. 브라우저 실측 중심 오차는 `0px`다. 열린 행·버튼·메뉴의 계층은 각각 `1050`·`1070`·`1080`으로 분리해 메뉴가 뒤쪽 토론 카드에 가려지지 않게 했다. 실제 열린 메뉴 좌표에서 최상위 요소가 메뉴 내부 요소임을 확인했다.

환영 Hero는 데스크톱 기준 `361px`에서 `127.89px`로 줄였다. 상단 로고 높이는 `34px`, 타이틀 글자는 `28px`로 맞춰 타이틀이 로고보다 작고 다른 본문 글자와도 지나치게 차이 나지 않게 했다. 왼쪽 카테고리 메뉴는 `190px`에서 `240px`로 넓혔고, 태그 페이지의 `토의 시작` 버튼은 도구 모음 내부 오른쪽 넘침 `0px`로 확인했다.

태그 페이지는 서로 붙어 있던 원색 블록을 데스크톱 3열·18px 간격의 독립 카드 Grid로 바꿨다. 카드 본문은 흰색, 제목은 Ink, 설명은 Muted 색상으로 통일하고 태그 고유 색상은 4px 상단 강조선으로만 유지했다. 최근 토론은 옅은 블루 배경·경계·`최근 토론` 레이블을 갖는 76px 독립 패널로 분리했다. 보조 태그 7건은 주요 태그 아래의 별도 구역에 실제 설명과 함께 데스크톱 4열·12px, 모바일 1열·10px로 배치했다. 모바일 주요 태그는 폭 336px의 한 열 카드와 14px 간격으로 전환하며 가로 넘침은 `0px`다.

최근 토론 날짜 중 절대 날짜는 `26년 6월 12일`, `26년 7월 7일`처럼 `00년 0월 0일` 형식으로 통일했다. `7일 전`, `9일 전`과 같은 상대 날짜는 의미를 유지했다. 검증 중 Flarum의 Font Awesome 웹폰트가 Cache 재생성 뒤 요청되지 않아 아이콘 전용 코드가 사각형으로 보이는 결함도 확인했다. 의미 Class는 유지하고 검색·내비게이션·태그·게시물 작업·Footer 아이콘을 시스템 단색 기호로 치환해 화면의 웹폰트 전용 깨진 문자를 `0건`으로 줄였다.

Hero의 위·아래 패딩은 데스크톱 `19px`, 모바일 `17px`로 대칭화했다. 데스크톱에서 타이틀 위와 마지막 설명 아래의 실제 여백 차이는 경계선 포함 `1px`다. 목록 작성자 아바타의 기존 13px 상단 여백을 제거해 아바타와 제목의 세로 중심 차이를 `12px`에서 `0px`로 줄였다.

게시물 작업은 답장·좋아요·해결 선택·더 보기를 모두 아이콘과 한글 텍스트 조합으로 표시한다. 기존 `top: calc(100% + 8px)` 방식은 본문이 길어질수록 카드와 버튼 사이가 8px에서 39px·49px·66px로 늘어나는 원인이었다. 이를 카드 하단 기준 고정 앵커로 바꿔 짧은 본문과 긴 본문 모두 설계 간격 8px, 보더를 제외한 브라우저 실측 7px로 통일했으며 게시물별 편차는 0px다. 작업 그룹은 Flex로 배치하고 데스크톱 8px, 모바일 6px 간격을 적용해 버튼 사이 겹침을 0px로 유지한다. 모바일 390px에서도 네 버튼이 한 줄에 유지되며 가로 넘침은 0px이다. 버튼 뒤를 지나던 Flarum 기본 게시물 구분선은 카드 보더와 역할이 중복되어 제거했다.

작성창과 태그 선택창에서 확인한 규칙을 특정 창 전용으로 두지 않고 Flarum의 공통 `Modal` 구성요소에 적용했다. 모든 대화상자는 같은 58px 헤더, 블루 계열 경계, 원형 닫기 버튼, 주요 확인 버튼, 입력 배경과 2px의 부드러운 포커스 링을 사용한다. 브라우저 기본 고대비 이중 외곽선은 제거하되 키보드 포커스 자체는 색과 링으로 계속 구분된다. 태그 선택창의 직접 노출 영문 `Choose`, `OK`, `Bypass tag requirements`는 `주 태그를 선택하세요`, `확인`, `태그 필수 조건 무시`로 변경했다.

홈 좌측 상단의 작동하지 않는 버튼은 Flarum의 모바일 `Navigation-drawer`를 이전 테마 CSS가 데스크톱에 강제로 노출한 것이었다. 클릭하면 `drawerOpen` 상태만 추가되고 데스크톱 서랍은 열리지 않았다. 데스크톱에서는 이 중복 버튼을 `0x0`으로 비노출 처리하고, 모바일에서는 버튼 `40x46px`, 실제 서랍 `270px`가 열리는 기존 동작을 유지했다.

프로필은 공통 배경색만 적용되던 상태에서 전용 레이아웃을 추가했다. 사용자 Hero를 165px 블루 Gradient 영역으로 정리하고 96px 아바타, 이름, 가입·활동 정보를 명확히 구분했다. 데스크톱 메뉴는 `240px`, 콘텐츠는 `780px`로 배치했으며 빈 화면을 독립 카드로 만들었다. 모바일은 프로필 정보를 압축하고 메뉴와 콘텐츠를 한 열로 전환한다. `Likes`, `My media`, `Security`, `best answers`는 `좋아요`, `내 미디어`, `보안`, `해결 답변`으로 번역했으며 Locale warm-up이 네 핵심 키를 실제 값으로 검증하도록 강화했다.

설정과 보안 화면은 프로필 전용 디자인 체계 안으로 통합했다. 계정·알림·개발자 토큰·활성 세션·전역 로그아웃을 16px Radius의 흰색 카드로 묶고, 블루 경계·그림자·버튼 상태를 공통화했다. 알림 표는 옅은 블루 헤더와 88px 웹·이메일 열로 정리했다. 모바일에서는 336px 카드 안에 302px 표를 배치해 페이지 가로 넘침을 `0px`로 유지했다. `New Token`과 Best Answer·Rich Text 확장 알림 문구를 포함한 직접 노출 영문은 0건이다.

고정 Footer의 ABLECLOUD Home, Blog, Online Docs 링크는 데스크톱 38px·모바일 36px 원형 아이콘으로 바꿨다. 기존 링크 문구는 DOM의 접근 가능한 이름으로 유지하고, 로드되지 않아 깨진 사각형으로 보이던 `fal fa-home` 요소는 숨겼다. 콘텐츠 하단에는 Footer보다 큰 64px·58px 여백을 확보했다.

### 답변 상태

| 상태 | 표시 | 사용자 의미 |
|---|---|---|
| 일반 질문 | 흰색 | 사용자가 등록한 질문과 첨부 |
| AI 기술지원 | 파란색 | 해결을 위해 진행 중인 전문 엔지니어 답변 |
| 추가 확인 필요 | 노란색 | 로그·화면·환경 등 추가 자료가 필요한 상태 |
| 최종 해결 가이드 | 녹색 | 질문자가 해결 답변으로 선택한 Knowledge Base |

상태 표시는 사용자에게 내부 근거 ID, 코드 경로와 검토 절차를 노출하지 않는다. 추가 확인 상태는 TechFlow가 `data-techflow-kind="needs-information"` 또는 전용 Class를 부여할 때 적용된다.

선택된 해결 답변은 연한 녹색 면, 좌측 녹색 강조선, 28px 높이의 작은 배지로 정리했다. 원 질문 안의 선택 답변 미리보기는 작성자·날짜·중복 배지를 숨기고 `선택된 해결 답변`과 본문만 보여준다.

### 한글과 접근성

- 해결됨, 해결 답변으로 선택, 해결 답변 선택 취소, 해결된 답변을 사용자 언어로 표시한다.
- 입력 글자는 16px, 모바일 주요 조작 영역은 44px 이상이다.
- 키보드 `:focus-visible`은 대화상자와 작성창에서 2px의 부드러운 블루 링을 사용하고 나머지 주요 조작 영역은 기존 3px 접근성 링을 유지한다.
- `prefers-reduced-motion`에서 애니메이션을 최소화한다.
- Primary/White 4.5:1 이상, Ink/White 12:1 이상, Solution text/background 6:1 이상의 자동 명도 대비 계약을 통과했다.

## 한글 Locale 결함 보완

검증 중 스테이징에서 Symfony Locale Catalogue가 빈 상태로 남아 `core.forum.*` 키가 화면에 노출되는 기존 결함을 재현했다. `php flarum cache:clear` 이후 빈 Catalogue를 제거하고 첫 웹 요청 전에 한국어 Catalogue를 명시적으로 warm-up하는 절차를 테마 자산에 포함했다.

최종 브라우저 검사에서 원문 `core.*` 키는 0건이었다. Locale warm-up은 검색·보안·좋아요·내 미디어를 각각 `검색`, `보안`, `좋아요`, `내 미디어`로 해석했으며 FoF Best Answer 검색 상태도 `해결된 토론`, `해결된 토론 검색`으로 표시됐다. 화면 제목은 `ABLESTACK Users Forum`으로 정상 표시됐다.

## 롤백 결과

테마 확장을 비활성화하고 Cache와 한글 Locale을 재생성했을 때 HTTP 200이 유지됐고 콘텐츠·첨부 해시는 기준선과 같았다. 같은 Package를 다시 활성화했을 때도 결과가 동일했다.

롤백은 테마 비활성화만 사용하므로 질문, 답변, 첨부, 계정, 검색과 TechFlow 자동화 상태를 건드리지 않는다.

현재 구현은 Chrome, Edge, Firefox, Safari의 현대 버전을 대상으로 한다. 오래된 브라우저에서는 AI 상태 Badge의 `:has()` 기반 자동 감지가 생략될 수 있으나 질문 읽기와 기본 테마는 유지된다.
