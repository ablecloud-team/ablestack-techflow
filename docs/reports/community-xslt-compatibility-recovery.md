# Community Chrome158 호환성 복구·원인 분석

관련 Issue: #164. 운영 복구일: 2026-11-26 KST. Flarum1.8.18·기존 테마 유지.

## 원인

Mac Chrome에서 초기 화면의 카테고리·요약·썸네일이 사라졌다. 캡처에는 `XSLTProcessor is not defined`와 로컬 XSLT 보완 파일404가 함께 있었다. CSS는 로드됐지만 JavaScript 초기화가 중단되어 테마의 목록 보강과 메뉴 구성이 완성되지 않은 상태였다.

- Flarum의 `Formatter/XsltPolyfill.php`와 `Frontend/Document.php`는 네이티브 API가 없으면 `assets/xslt-polyfill/xslt-polyfill.min.js?v=1.0.23`을 요청하도록 구성돼 있었다.
- 설치된 Core의 `js/dist/xslt-polyfill/`에는 메인 JS와 `dist/xslt-wasm.js`가 있지만 공개 assets 경로에는 둘 다 없었다. 기존 배포·예행연습 스크립트에 `assets:publish`와 해당 파일 검증이 빠져 있었다.
- [Chrome 공식 변경 안내](https://developer.chrome.com/docs/web-platform/deprecating-xslt)는 Chrome158 안정판의 네이티브 XSLT 제거를2026-11-17로 명시한다. 사용자는 Windows157에서 정상, Mac의 API 제거 상태에서 실패한 뒤 Windows158 업데이트 후에도 복구 상태가 정상임을 확인했다.

따라서 최근 테마 코드 변경이 아니라 **브라우저 기능 지원 변화가 기존 배포 자산 누락을 드러낸 것**이라는 판단이 증거와 일치한다. 단, 최초 설치 때 누락됐는지 이후 어느 시점에 삭제됐는지까지 기존 로그만으로 단정할 수는 없다. 누락을 만드는 특정 사용자나 삭제 작업은 확인되지 않았다.

## 변경 이력 대조

- 운영 UI JS/CSS·테마 파일 수정 시각은8월29일이며, 소스는 줄바꿈을 정규화하면 저장소 main과 일치했다. 외관 설정·활성화 확장 목록의 SHA-256도 작업 전후 동일하다.
- 공개 `forum.js` SHA-256: `3b15f5671d13ba6ef0dcfa142e9bf36e63a5b73e6ca612020b8168aa1f28d279`.
- 공개 `forum.css` SHA-256: `ab935e5403efe270f2157cba7a6fc2e8dfe769041012a9f661e4fd8347b633ae`.
- 확인한 access.log 범위에서 보완 파일404가 반복됐고, Chrome158 요청이 포함됐다. 원문 로그·주소·계정 정보는 저장소에 복제하지 않았다.
- 수정 시각·해시가 변경되지 않았다는 사실과 로그 범위의 한계를 구분한다. 이를 모든 과거 운영 작업이 없었다는 증명으로 일반화하지 않는다.

## 운영 조치

1. 기존 UI 자산·테마 파일과 해시를 보호된 백업에 보존했다.
2. 외부 새 라이브러리 설치나 Core 업그레이드 없이 이미 설치된1.0.23 패키지의 두 파일만 공개 경로에 게시했다. 원본·공개 파일 SHA-256을 대조했다.
3. 기존 UI JS/CSS, 외관 설정·권한·AI 엔진·서비스 설정은 변경하지 않았다. DB 복원, 테마 비활성화, 서비스 재시작도 하지 않았다.
4. 별개로 토론209의 코드 블록에서 Highlight.js 추가 언어가 Core보다 먼저 실행되는 오류를 재현했다. AI 소유 게시물602의 코드 언어 표기만 `nginx`→`text`로 조정해 해당 추가 언어 다운로드를 피했다. 기술지원 본문과 설정 코드 내용은 그대로이며 Case 기록도 동기화했다. 범용 외부 로더 자체를 교체한 것은 아니다.

## 검증

- 두 파일 외부 HTTPS200 및 `application/javascript` 확인.
- 일반 브라우저에서 카테고리10개·요약20개·로드된 썸네일6개와 콘솔 오류 없음 확인.
- 별도 합성 HTML에서 네이티브 `XSLTProcessor`를 제거한 상태로 XML→HTML 변환이 `xslt-compat-pass`를 출력하고 콘솔 오류가 없는 것을 확인했다. 실제 페이지의 네이티브 API를 덮어쓰지는 않았다. 검증 HTML은 공개 경로에서 회수해 백업으로 이동했다.
- 사용자가 실제 Mac Chrome과 업데이트한 Windows Chrome158에서 초기 화면 정상 복구를 확인했다. Safari·Firefox·다른 기기를 모두 시험한 결과로 일반화하지 않는다.
- 기존 토론149개·게시물494개·첨부 레코드183개는 유지됐다. 작업 중 사용자 수는 별도 활동으로 증가했으므로 전체 DB 해시 불변을 주장하지 않는다. 사용자 계정은 생성·수정하지 않았다.
- 배포 계약/기존 UI 시험26개와 PHP CLI 검증 실행8개 통과. 로컬 전체34개 발견 시험은 PHP 없는 환경에서8개 건너뛰었으며, 이8개를 서버의 PHP CLI에서 별도로 통과시켰다.
- PHP 검증기는 정상·구버전·누락된 메인/의존 파일·빈 파일·내용 불일치·허용 경로 위반을 검사한다. 테스트는 임시 합성 파일만 사용한다.

## 재발 방지와 롤백

- 테마 적용·Core/테마 예행연습에 표준 자산 게시를 추가했다. 새 읽기 전용 검증기로 설치 파일과 공개 파일의 존재·비어 있지 않음·동일 해시를 검사한다.
- 브라우저 버전과 네이티브 XSLT 없는 조건을 UI 완료 기준에 포함했다. 네이티브 API가 있는 브라우저에서만 시험했던 기존 검증 범위의 부족을 보완한다.
- 운영 긴급 복구는 이미 적용됐다. 재발 방지 스크립트 수정은 별도 PR 검토 대상이며 무관한 PR #163을 병합하거나 AI 엔진을 배포하지 않는다.
- 롤백은 이번에 추가한 두 자산과 게시물602의 언어 표기만 대상으로 한다. 기존 UI 파일·DB를 광범위하게 되돌리지 않는다. 단, 보완 자산을 제거하면 Chrome158 장애가 재발하므로 대체 복구가 검증되기 전 제거하지 않는다.
