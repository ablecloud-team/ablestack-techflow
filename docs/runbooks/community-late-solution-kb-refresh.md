# 해결 이후 추가 보고에 따른 KB 최신화

관련 Issue: #146. 재현 사례: [Community #199](https://community.ablecloud.io/d/199-gfs-seutoriji-guseong-oryu).

## 문제와 변경

기존 엔진은 해결 선택이 바뀌었을 때만 KB를 생성했다. KB가 선택된 뒤 들어온 사람 댓글은 기록만 하고 KB를 재작성하지 않았다. 예약 작업도 완료 ID를 영구 제외하여 이후 수정된 실제 해결 결과를 놓쳤다.

이제 해결 상태이고 기존 AI 소유 KB가 현재 솔루션으로 선택된 토론에서, KB 이후 새 사람 댓글이 실행 성공을 보고하면 현재 공개 원문과 작성자를 다시 확인한다. 질문·제안·인용·미해결 내용은 갱신 근거로 사용하지 않는다. 기존 KB 자신을 종합 입력에서 제외하고 최신 사람 보고를 잘리지 않는 고정 구간에 넣어 과거 AI 가설의 재강화를 방지한다. 내부 검색어에서도 Community/Knowledge/Base 같은 포장 문구가 실제 한국어 증상을 덮지 않게 한다.

같은 KB ID를 수정하고 기존 해결 선택 출처는 유지한다. 보고자가 질문자가 아니면 질문자가 확인했다고 쓰지 않는다. 새 KB나 일반 AI 답글을 덧붙이지 않는다. 기존 KB를 다른 글로 바꿔 선택한 경우에는 후속 댓글 경로가 임의로 되돌리지 않는다. 질문자·검증된 관리자의 새로운 해결 선택 이벤트는 기존 권한 확인 절차로 처리하며 이때에도 기존 KB를 같은 위치에서 갱신하고 새 선택 출처를 기록한다.

## 재시도와 저장

- `community_case.source_metadata` JSON의 `knowledgeBaseRefresh`는 진행 중 원본 ID·해시·작성자·순번을 보관한다. `knowledgeBaseRevision`은 성공한 갱신 출처이다. 별도 테이블·열·DB migration은 없다.
- 생성 또는 공개 수정 실패 시 기존 KB를 보존하고 미완료로 둔다. 게시 성공 후 선택 확인 실패는 다음 실행에서 게시를 반복하지 않고 선택 확인만 재시도한다.
- 진행 중이면 Poller가 해당 입력을 완료로 체크포인트하지 않는다. 숨김·삭제·미해결 내용으로의 수정은 해당 대기를 취소한다. 정상 재질문으로 토론이 재개되면 옛 갱신 메타데이터를 제거한다.
- 게시 직전에 원문·공개 상태·현재 솔루션·케이스 상태를 다시 대조한다. 중복 입력과 역순 입력이 최신 갱신을 덮지 않게 한다.
- 현재 배포 구성의 단일 Gateway worker 내 잠금으로 중복 동시 갱신을 직렬화한다. 여러 프로세스/replica 배포의 분산 잠금을 보장하는 변경은 아니다. 다중 worker 전환 전에는 별도 분산 조정이 필요하다.
- 자동 인식은 보수적인 한국어 성공 보고 규칙이다. 과거 댓글 수정, 새로운 표현, 해결 선택 해제는 예약 재점검에서 실제 내용을 검토한다. 엔진이 모든 표현을 자동 판정한다고 가정하지 않는다.

## 예약 작업

원본 프롬프트는 [community-scheduled-review-prompt.md](community-scheduled-review-prompt.md)이다. 기존 `ablestack-community-kb` 작업을 갱신하며 KST 00:00/12:00 주기는 유지한다.

신규 토론은 최초 등록 2026-11-04 00:00 KST 이후로 한정한다. 이미 명시적으로 검토한 KB는 날짜와 무관하게 추적하며 #199/KB550을 포함한다. 완료 기록은 사람의 공개 댓글·수정·현재 해결 선택 지문이 같을 때만 건너뛴다. AI 자체 수정은 지문에 넣지 않는다. 지문 없는 기존 완료 기록은 최초 한 번 재검토한다. 권한·게시·PR 단계가 실패한 항목은 완료로 바꾸지 않는다.

읽기 전용 선별 예:

```powershell
python tools/community_review_candidates.py --ledger "$env:LOCALAPPDATA/ABLECLOUD/TechFlow/community-scheduled-review.json" --assistant-user-id <확인한-AI-사용자-ID>
```

Python 명령이 없으면 설치된 승인 Python 실행 파일을 사용한다. 도구는 공개 API 페이지를 순회하고 본문을 메모리에서 해시해 메타데이터만 출력한다. 게시·상태 파일 쓰기·완료 처리는 하지 않는다. 출력의 `needsReview`는 검토 후보이지 자동 게시 승인이나 실제 해결 판정이 아니다. 현재 선택 답변 관계를 포함해서 읽고, API 오류/페이지 루프/작성자 누락은 실패로 남긴다.

## 검증과 배포 경계

#199의 원래 해결 출처 548, KB550, 후속 성공 보고559를 재현한다. 같은 KB·원 해결 출처 보존, 생성/게시/선택 실패 재시도, 중복·역순·동시 입력, 숨김·내용 변경·선택 해제, 질문자 재개와 예약 선별을 시험한다. 모델·Flarum을 모의한 로컬 회귀시험이며 실모델 답변 품질이나 운영 엔진 배포 검증은 아니다. PostgreSQL 경로는 SQL 인자/JSON 보존 계약 시험으로 검증하며 실 DB 통합시험과 구분한다.

이번 변경은 PR 등록과 기존 예약 프롬프트 갱신까지이다. 운영 엔진은 PR 병합·승인된 배포 후 버전 0.16.29와 기존 서비스 정상 상태를 확인한다. GitHub→Chat 보호 서비스나 다른 서비스 설정은 변경하지 않는다.
