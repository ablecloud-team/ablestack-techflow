# 암호화 지원 첨부 처리 절차

## 현재 확인된 제약

Discussion #186의 0918.zip은 926,602,290바이트이며 714개 항목을 포함한다. ZIP 항목의 암호화 플래그를 확인했고 로그 본문은 읽지 않았다. 암호가 제공될 때까지 원인 확정은 보류한다.

현재 Chat 일반 질문은 `main.py`의 `record_chat_turn`을 통해 DB에 저장되고 AI 분석으로 전달된다. 따라서 봇 비공개 대화에 암호를 일반 메시지로 보내는 것도 안전한 일회성 접수 방식으로 취급할 수 없다. Synology 자체 메시지 보관·알림·백업도 별도이므로 TechFlow의 삭제만으로 제거를 보장할 수 없다.

## 즉시 적용 원칙

1. 파일 UUID·원본 크기·암호화 여부를 확인하고, 이미지 등 읽을 수 있는 첨부부터 분석한다.
2. 공개 답변에는 읽은 자료와 읽지 못한 자료를 분명히 구분한다. 암호화 파일을 읽었다고 쓰거나 파일명만으로 원인을 단정하지 않는다.
3. 공개 댓글에 암호를 쓰도록 요청하지 않는다. 현재는 민감정보를 제거한 필요한 로그를 암호 없이 제출하는 방법을 안내한다.
4. 암호화 감지는 분석 서비스 장애가 아닌 사용자 자료 대기 사유다. 동일 파일의 암호를 반복 요청하거나 같은 파일을 계속 재분석하지 않는다.
5. 사용자가 암호 확인 중이라고 알리면 이미지 기반 초기 안내를 유지하고 로그 분석은 대기한다.

## 채택 방향: 관리자 Chat 알림 → 관리자 암호 확보 → 엔진 일회성 전달

Chat 사용자는 Community 게시자가 아니라 관리자다. 게시자와 Chat 계정 연결은 요구하지 않는다. 게시자는 관리자에게 암호를 전달하고, 엔진 접근은 별도로 인증된 관리자만 수행한다.

1. 첨부를 `WAITING_FOR_SECRET`으로 기록한다. 공개 답변에는 접수 번호와 대기 사유만 표시한다.
2. 봇은 지정된 관리자에게 비공개 Chat으로 토론 링크·접수 번호·파일명·암호 필요 사유를 한 번 알린다. 암호 자체는 알림에 포함하지 않는다.
3. 관리자가 게시자에게 암호를 확보한다. 승인된 관리자 인증과 Case·첨부 접근 권한을 확인한다. 접수 번호를 안다는 이유만으로 전달 권한을 허용하지 않는다.
4. 관리자는 엔진의 전용 비밀 제출 경로에 Case ID·첨부 UUID·암호를 전달한다. 기본 운영 인터페이스는 화면에 표시되지 않는 대화형 입력이며 셸 인수·환경 파일·명령 이력에 암호를 넣지 않는다. HTTPS API 또는 전용 관리 입력창은 같은 일회성 비밀 경계를 사용한다. Chat 일반 메시지를 비밀 제출 API 대신 사용하지 않는다.
5. 암호 입력 요청은 일반 대화 DB, LLM 요청, 분석 추적, 프록시 본문 로그, 오류 로그와 분리한다. 비밀 수신 서비스가 메모리 또는 짧은 TTL의 전용 비밀 저장소에서만 보관한다. Chat에 원문 암호를 반환하지 않는다.
6. 격리된 복호화 작업은 지정된 첨부에만 접근한다. 총 해제 크기·파일 수·중첩 깊이·시간·메모리 제한, 경로 탈출과 링크 검사를 유지한다. 실패 시 재입력 횟수를 제한한다.
7. 복호화 후 텍스트 로그와 이미지 등 지원 형식만 선별하고 비밀정보를 제거한 Artifact를 등록한다. 서버 전체 로그 묶음의 바이너리 journal·중첩 회전 압축 로그는 별도 검증 없이 일괄 허용하지 않는다.
8. 성공·실패·취소·만료 시 비밀과 임시 평문을 폐기한다. DB에는 첨부 식별자, 처리 상태, 시각, 제출자와 정형 오류 코드만 남긴다.
9. 원래 Case를 재개해 기존 이미지·질문·새 로그를 함께 분석하고 중복 답변을 방지한다. Community에는 암호나 비밀 입력 링크를 게시하지 않는다.

## 완료 조건

- 타인의 접수 번호, 만료 링크, 재사용 링크, 잘못된 암호로 접근할 수 없음
- 암호가 Chat 메시지·TechFlow DB·LLM·운영 로그·모니터링·덤프에 남지 않음
- 재시작·취소·실패 뒤 비밀이 잔존하지 않음
- 암호화 자료 대기는 반복 장애 알림을 만들지 않음
- 이미지 선행 분석과 후속 로그 분석이 같은 Case에서 이어짐
- 실제 암호화 ZIP, 잘못된 암호, 큰 로그 묶음, 중첩 압축, 경로 탈출, 중복 제출 검증

이 문서는 후속 비밀 전달 기능의 설계다. 현재 배포에는 암호화 ZIP 감지·명확한 안내와 기존 권한 내 파일 주소 해석이 포함되며, 담당자용 비밀 제출 API/CLI 및 자동 복호화 재개가 구현된 것으로 안내하지 않는다.
